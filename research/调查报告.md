# Oopz 广告与直播状态调查

调查日期：2026-10-11（Asia/Shanghai）。本报告区分公开资料中的事实、代码分析推断和待验证项；没有登录账号或运行最新官方 Windows 安装包验证广告展示。

## 版本范围

- 调查时的 Windows 下载入口为 [Oopz 官方下载](https://www.oopz.cn/download/xx)。对该入口进行只读 HEAD 请求，最终重定向到 [oopz_setup_v1.4.6.1.exe](https://downloadcdn.oopz.cn/release/146/oopz_setup_v1.4.6.1.exe)，响应长度为 253,019,040 字节，Last-Modified 为 2026-09-14 02:23:04 GMT。这证明 2026-10-11 官网分发的安装包名称为 **1.4.6.1**。
- 本机客户端的 `data/flutter_assets/assets/version` 内容为 **0.88.41**，安装目录为 `%LOCALAPPDATA%\oopz`。不能据此把本机程序等同于官网 1.4.6.1，也不能保证相同补丁在两者上通用。
- [官方网页客户端](https://web.oopz.cn/) 在调查时公开的 HTML 指向 Flutter 构建目录 `/web/00880530f5613f7tgk9/`。本报告的公开代码分析来自该构建的 [main.dart.js](https://web.oopz.cn/web/00880530f5613f7tgk9/main.dart.js) 和 [main.dart.js_3.part.js](https://web.oopz.cn/web/00880530f5613f7tgk9/main.dart.js_3.part.js)。网页与 Windows 客户端可能共享模型，但不能把网页代码当作本机版本逐字一致的证明。

## 可确认的公开事实

1. [官方隐私政策](https://help.oopz.cn/agreement/privacy) 第 1.2 节设备信息明确列出 PC 端的“进程及软件列表”。它证明官方声明了这类信息收集范围；未披露具体直播软件名单、判定算法、扫描频率或结果用途。
2. [官方服务协议](https://help.oopz.cn/agreement/service) 第七节包含广告、推广与宣传信息，提到站内信、系统推送和弹窗等渠道。协议描述产品能力，不足以证明当前 Windows 客户端每个广告位实际在展示。
3. 官方公开客户端代码含实际广告列表请求及三类广告模型：`AREA_ADV`（域广告）、`LOGIN_ADV`（登录广告）、`SHOP_ADV`（商城广告）。创意模型含 `id`、`version`、`imgBlack`、`imgWhite`、`jumpInfo`、`isNeverDisplay` 和按钮图片等字段。
4. 公开代码有 `broadcastCount`、`broadcasting`、`obsBroadcasting` 状态字段。仅这些字段不足以证明 Windows 端如何识别 OBS、是否识别正在推流或仅识别进程存在。

## 广告请求及失败处理

下表为上述公开构建中的静态代码事实。方法名为编译后名称，仅用于复核。

| 广告来源 | 请求与模型 | 失败处理 |
| --- | --- | --- |
| 域广告、登录广告 | `A.aHi.ayE` 请求 `GET /advertisement/v2/list`；`A.aqg.atO` 读取返回数据 `advs.AREA_ADV`、`advs.LOGIN_ADV` | 当响应成功标志为 false，记录错误并仅设置已加载状态后返回；没有显式把现有域广告、登录广告列表清空。该方法没有自己的异常 catch 分支。 |
| 商城广告 | `A.aqg.atP` 经 `jn.azM` 请求 `GET /uni/advertisement/v1/list`，参数 `types=SHOP_ADV`，读取 `advs.SHOP_ADV` | 成功标志为 false 或捕获异常时，明确置为空列表，再更新商城广告状态。未发现回落预置广告或旧商城列表。 |
| 开发模拟数据 | `A.aqg.atO` 检查 `XX_DEV_ENABLE_NEW_AD_MOCK` | 仅该开关严格等于 true 才进入内置模拟广告分支。请求失败本身不会启用模拟分支。此次未读取运行时开关值。 |
| 本地广告历史 | `A.aGl.Ph`、`A.aGl.xR` 读写 `ad / ad_local_cache / ad_history` | 该处存储以逗号分隔的历史 ID；未发现这条路径储存完整广告创意作为请求失败后的回落内容。 |

初始化方法 `A.aqg.bC` 会清空域广告和登录广告列表、读取广告历史，再调用 `atO`。因此，**若 HTTP 404 被公共网络层转换为失败响应**，首次初始化后的域/登录广告列表预计保持为空；在广告已经成功载入后的刷新阶段，失败响应则可能保留已有内存列表。这是从状态更新逻辑得出的推断，尚未作为本机 0.88.41 的运行结果验证。

域广告与登录广告共用 v2 列表；商城广告使用另一个 v1 列表。只处理其中一条请求不能覆盖三类广告。推荐/发现页面还解析独立响应中的 `advertisementBannerList`、`entertainmentSection.adBanner`、`adSection` 和 `banners` 等字段，因此也不能把这两条列表请求视为所有推广内容的唯一来源。

## 独立发现页广告字段

2026-10-11 复核同一份[官方公开客户端延迟脚本](https://web.oopz.cn/web/00880530f5613f7tgk9/main.dart.js_3.part.js)，发现如下静态事实：

| 广告字段 | 所在请求 | 字段缺省或为 null 时的解析及显示 |
| --- | --- | --- |
| `advertisementBannerList` | `GET /discovery/v3/home` | 列表读取器默认返回空列表；发现页两种横幅组件 `A.eVC`、`A.eVQ` 在列表为空时返回空组件。 |
| `entertainmentSection.adBanner` | 同一发现页请求 | Map 读取器默认返回空 Map，再生成图片地址、跳转地址、ID 都为空的非 null 模型；`A.eW0` 检查图片地址长度，长度为零时返回空广告组件。 |
| `adSection` | `GET /uni/playmate/v2/home` | 默认生成空标题与空域列表；`A.ePi` 只在该广告区列表非空时添加广告区组件。`freeSection` 有独立读取及非空判断。 |

同一页面的默认状态也使用空横幅列表、空广告图片模型及空广告区列表。非首页标签切换会保留已有广告状态作为空响应的回落；冷启动时这些状态默认为空。这是公开网页构建的行为，不能据此直接声称 Windows 构建已经完成登录后界面验证。

本机原始 `app.so` 中三个字段各对应一个规范 Dart 字符串对象，读取到的原始长度、哈希为：`advertisementBannerList`：23 / `0x2578083F`；`adBanner`：8 / `0x0451BA67`；`adSection`：9 / `0x1C7C5BA1`。全部识别到的 79,630 个 Dart 字符串对象哈希均与计算值匹配。该证据确认字段存在及字符串格式；此次未完整反汇编本机解析器和 UI，以证明其与公开网页构建逐指令一致。

仅使这三个明确广告键不被读取，预计不会阻断同一响应中的普通推荐列表、娱乐列表、免费专区与匹配信息；这是依据字段独立读取形成的实现推断。通用 `banner`、`banners` 还用于非广告业务，不能仅凭名称一并停用。

## 实现与验证边界

- 公开网页逻辑与本机静态字符串尚不能证明 Windows 0.88.41 的完整直播检测链；窗口查询过滤仅覆盖已实现的查询路径。
- 把请求路径改为不存在的路径，是让请求失败的做法，不等于给客户端提供经过验证的成功空响应。公共网络层的异常转换、重试、已有内存状态和不同推广接口都可能影响结果。
- 把 DLL 放入根目录是否自动加载，必须由目标程序的真实依赖和加载测试确认；任意文件名的 DLL 不会因为存在于目录中就自动生效。
- 本报告不声称最新官方 Windows 客户端广告位或 OBS 检测已完成运行验证，也不声称可以阻止所有信息收集。
